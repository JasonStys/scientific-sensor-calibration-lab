# Release, acceptance and rollback

1. Review model/input/uncertainty assumptions, numerical contracts, security and notices. Run C# restore/build/self-tests/format, Python lint/types/tests/coverage, Node format/unit/build/browser/audit, Python dependency audit and inventories. Build/smoke actual local portable app.
2. Check live Actions artifact bytes and fresh billing meter separately from cache allowance; alert on capacity. No automatic cleanup, retention changes or reuse of prior deletion approval. Workflows upload no Actions artifacts/caches.
3. Commit/push reviewed source to main. Require newest successful exact-commit **Validation(8 jobs)** and **CodeQL(3 jobs)**. Query open findings separately; a successful analysis upload is not evidence of no alerts.
4. Dispatch Portable release with a new numeric semantic version. It refuses missing passing workflows or malformed versions and creates only a draft on the exact SHA. Three runners publish self-contained C# runtime, execute native self-tests, freeze the whole app with notices, smoke it and upload ZIP/checksum directly to draft. Nothing publishes automatically.
5. Download every asset to a private acceptance folder. Verify metadata digest, adjacent checksum, CRC, confined members and notices/resources. Execute only newly built reviewed assets, not arbitrary archived executables. Test downloaded Windows CLI/export/replay/history/HTTP and all36 browser cases against it. Linux/macOS execution evidence comes from their runners.
6. Record SHA, run links, counts/coverage/audit scope, model limits, unsigned notice and ZIP digests in release notes. Recheck final gates, publish draft, confirm tag/main/release SHA and public downloads. Stop only owned previews/test servers and close temporary tabs; leave other user apps untouched.

Extract-and-launch does not install a signed app or grant admin rights. Keep whole `_internal`/native directory. Supported binary architectures are Windows x64, Linux x64 and macOS arm64. Source can be inspected/rebuilt elsewhere but compatibility is not promised without tests. On Unix, restore executable permissions if your ZIP extractor omits them according to OS policy; never disable security protections.

Rollback: unpublish faulty release to draft, communicate the limitation and preserve source/evidence. Ship a new version after full gates; do not rewrite public tags or silently replace assets. No accounts, remote hardware, automatic updater or schema migrations exist. Histories are unencrypted local files; choose separate new files rather than deleting old evidence. Never overwrite a user's uncommitted source/data during rollback.
